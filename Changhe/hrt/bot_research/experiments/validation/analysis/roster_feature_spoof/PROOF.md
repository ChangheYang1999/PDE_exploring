# Changing a public feature used for opponent selection

## Statement and hypotheses

The target is P5TNUBM from frozen lead v30 with its existing r1_poke parameter set to0,2,3 or4. Every other parameter stays at the declared nominee setting. The counter policies are the old threshold selector, the new exact-count selector, and both forced branches. This forms32 standard games including both assignments.

## Argument

The bundled observation reports the opponent roster and bought_round, so the selectors observe the changed count on round2. At that decision the old policy chooses early exactly when count>=3, while the new policy chooses early exactly when count=3. The branch controls separate the selector decision from the branches' actual performance. This is not a private-information attack: all changes are legal first-round purchases generated by the unchanged nominee implementation.

Altering r1_poke also changes gold, factories and damage. Thus a changed result cannot be attributed solely to the selector unless the same modified target is beaten by its alternative forced branch. Complete-history equality with the selected branch must also hold. Even then the causal statement is limited to these controlled whole-policy comparisons; no general inevitability theorem follows.

## Tests and scope

Before outcomes, declare the four r1_poke values and all four counter modes. Run strict accounting, independent engine replay, source/data checks, fresh decisions and observed selector predicate checks. Compare each adaptive history with its selected forced branch. The value3 serves as a control against the previously measured default nominee. A successful spoof means that one adaptive policy loses to a modified target while its alternative fixed branch wins; a draw is reported separately. These are adaptive development counterexamples, never held-out evidence. Pool C is unused.
