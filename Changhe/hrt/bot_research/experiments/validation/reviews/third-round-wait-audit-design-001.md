# Protocol 161 audit design

Written 2026-10-31T22:02:10Z. Actual model: GPT-6 Astra. This is a source-only design by the local reviewer, coordinated with the parent and the separate proof/policy author. No policy, engine, declaration or checker calls were executed for this design.

The prospective corpus consists of exactly four new standard-start games: T/H and T/S, each with T in physical seat 0 and seat 1. H has the exact HP_PARAMETERS specification already fixed in the preceding protocols. Only these four histories may be used for extra T and reference-member calls. Earlier G-selection branches at rounds 2 and 3 are source-reviewed but are not expected to be empirically exercised here.

T must select before component calls on the selection round. While uncommitted, it calls G and L4 once each, in that order, on separate copies of the actual public observation. Through round 3 it submits G's proposal. L4 is fresh WallSignalRepair with attack_round set to 4 before its first call. At the earliest round 2, 3 or 4 with any opponent building or roster, T selects G permanently. If that test stays false through round 4, T selects L4 permanently at round 4. After selection it calls only the selected member. The policy trace must retain ordered called members, every proposed list, the discarded L4 list, submitted actions and selection state using deep copies.

## Independent component-state audit

A separate audit phase constructs one fresh T, one independent G and one independent L4 for each new retained history. It advances the references only on rounds when T is specified to call the corresponding member, always on copies of the actual engine observation reconstructed by replay. The round-3 L4 proposal is recorded and compared with the L4 reference proposal, but is not required to equal T's submitted actions. The submitted list must equal G's proposal before selection and the chosen proposal after selection, and must exactly reproduce the retained T actions. No standalone L4 history transfer is asserted.

Compare freeze_state(vars(member)) for both members after each successful round. Also compare inactive member state before and after the call. Check T's own round, player, selected member, selection round and trace independently. Inspect G.trace, L4.trace, L4.repair_trace and the persistent H model's last_round/player. Full L4 snapshots include the bound H policy owner and therefore its persistent opening, defender and handoff fields. The independent reference L4 already supplies the H state and predicted actions needed for this comparison: no additional standalone H decision is needed.

The canonicalizer covers logical object fields, bound methods, function defaults and closure values. It does not establish shared-reference identity, module-global/cache equality, clock equality or equivalence outside supported acyclic values. Unsupported values must fail the audit. Exact state agreement here is a comparison on the actual public observations, not proof that discarded L4 actions occurred. The H model can be chronologically aligned while incorrectly predicting S. Report forecast-versus-real-opponent action agreement as a diagnostic separate from model-state agreement.

Use source-verified call paths plus trace increments to check successful nested calls. Do not wrap component objects or install profiling hooks, which could alter captured state or deadline behavior. Attempted but failed calls must be tracked separately because an exception can precede a trace append. Journal every top-level attempt before invoking it, then record completion or failure immediately. A interrupted call leaves an explicit pending attempt. Preserve a checkpoint after every completed round and an error receipt if subsequent work fails.

## Counts and hypotheses

For n completed actual T calls, let d be the number of completed rounds before permanent selection, or n if a terminal game ends while uncommitted. Successful internal G plus L4 calls total n+d. If G is selected, the counts are G=n and L4=d. If L4 is selected, they are G=d and L4=n. Without selection, each count is n. Internal persistent-H model calls equal L4 calls and are a nested subset. Independent reference G and L4 calls follow the same individual counts. These counts must be checked per case and per round, not merely summed.

Keep original campaign external decisions, the ordinary fresh both-policy audit, the additional actual T calls, independent reference G calls, independent reference L4 calls, internal G/L4 calls and nested H model calls in separate named fields. Nested calls are not added again to a field called fresh external policy calls. Failed and interrupted attempts remain visible and do not become successful calls. No extra control policy calls are authorized.

The four hypotheses are prospective. H1 requires nonnegative T WDL in all four conditions. H2 requires that all four games reach round 4 and satisfy the exact opening and branch statements in Claims 4 and 5, including T/S's round-4 G action. H3 compares the complete T/S histories with retained G/S controls in the same physical G seat. H4 compares the two complete normalized histories for each of T/H and T/S. A valid counterexample refutes a universal hypothesis; missing, failed or unaudited conditions remain open. A completed audit and a confirmed hypothesis are different flags.

H3 uses late-reserved-wall-counter-00-001/results/case0005.json for T in seat 0 and case0004.json for T in seat 1. The old candidate was S, so normalize the old history from side 1 minus its recorded candidate side. Pin the original S declaration, final receipt, jobs, results, replays, all four audit receipts and every original archived source byte. Require the current G/S policy closure, five explicit data files and bundled engine to agree with the original freeze. Exact whole-game transfer remains conditional on matching relevant deadline branches; the finite replay comparison may still refute empirical reproduction.

## Evidence and failure handling

Declaration pins the proof, protocol, completed reviews, checker, pipeline, full static source closure, both balanced configurations and the five explicit counter-policy JSON data files. New campaign freeze/archive checks must cover all active declared inputs. Strict accounting requires exactly four distinct jobs and four valid attempts, with no hidden retry, failure or unresolved case. Independently bind each strict, replay, data, fresh and component-state receipt to the exact job grid, result paths, frozen sources and total calls. Replay the complete stream from the initial records through its first terminal boundary, with no trailing records or omitted rounds.

Canonical history comparison keeps all game fields except public match/player labels and physical interleave order, relabels names consistently and normalizes the winner. Check both complete streams before normalization. An early terminal game is retained and refutes the stated round-4 reach claim; it must not disappear through an assertion that stops all case accounting.

The final checker enumerates all four declared new cases and both retained controls even if files are missing. It preserves raw attempt receipts, audit errors, per-case mechanism violations and first complete-history divergences. Pre/post hashes apply to every input actually used. The generic existing fresh checker buffers detailed call logs until completion; its interrupted-run detail limitation must remain explicit. The new component audit uses durable per-call and per-round records to close that limitation for its own calls only.

The sequential one-core pipeline checks declared hashes and at least 20 GB free before each child, refuses starts with less than 560 seconds remaining before 22:50 UTC, bounds execution at 530 seconds and gives process-group TERM/KILL cleanup at most five seconds each. It retains partial output and cleanup status. No server, JavaScript/TypeScript tooling, cluster, remote computation, GPU or Lean/lake work is involved.
