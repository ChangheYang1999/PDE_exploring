# Supplementary independent reader for final D evidence

This reader is prepared separately from the original experiment. Run it only after the parent confirms that the existing terminal campaign, publication and post-D source checks have finished. Preparation has inspected source schemas and declaration metadata, without opening D opponent/scenario values or running any policy, constructor, Engine, replay, game or checker. There is no empirical pass at preparation time.

The executable uses only Python's standard library. Its posthoc review authenticates declaration001, the selected note and candidate, all 85 original pins, the separately dated 95-pin supplement and ten added snapshots, earlier matching receipts and their available archives, and explicit pre/post supplement checks. The post check must be dated after final publication. Earlier receipts establish identity at those records, not continuous monitoring.

It reconstructs all 96 jobs directly from the declared JSON after authorization, checks three groups of 32 and both physical seats, joins every original result with its complete primary JSONL history, and authenticates the retained engine-replay and fresh-entry receipts. It compares the original recorded `decide` history with fresh direct `decide` and fresh default `make`: three histories, two API forms and two fresh regenerations. The reader performs none of those calls itself. Counts concern external policy invocations; private nested forecast calls are outside these receipts.

The reader recalculates outcomes, HP differences, ending rounds, primary runtimes, canonical trajectory counts and maximum timed wrapper calls. Prescribed prefix turns stay separate from real candidate calls. It checks all condition and child-log coverage, including failure-file precedence and complete terminal boundaries. The exact declared pipeline has one attempt per condition; documented recovery or retry campaigns require a separately scoped independent review and are rejected by this version.

Separation is checked against the archived input versions. Current append-only team streams are not substituted for the historical captured bytes. Every overlap, unresolved input and undated-input limitation remains visible. This reader authenticates the existing separation audit and its coverage; it does not rerun family normalization or named scenario generators. Protected-file end integrity remains a separate team check against the recorded starting state.

Run from the project root after explicit parent authorization:

```sh
PYTHONDONTWRITEBYTECODE=1 \
TMPDIR="$PWD/bot_research/tmp" \
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
nice -n 19 taskset -c 29 .venv/bin/python -B \
  bot_research/experiments/validation/reviews/terminal_final_independent_001/read_final.py \
  --campaign-and-postchecks-complete \
  --supplement-pre bot_research/experiments/validation/analysis/terminal_reserved_validation/verification/dependency_supplement_pre_d_002.json \
  --supplement-post bot_research/experiments/validation/analysis/terminal_reserved_validation/verification/dependency_supplement_post_d_001.json \
  --pipeline-log bot_research/runs/validation/reserved-D-final-001-pipeline.log \
  --output-name completed-review-001
```

The post-check filename above is an explicit future input, not an assertion that it exists. Supply the actual final post-check path if different. The script also requires the completed `analysis/terminal_reserved_validation/verification/final_candidate.json`, its declared campaign and all referenced original archives, replay/fresh receipts, separation snapshots, loss accounting and primary/child logs. All paths are relative to the project. The fixed declaration determines campaign and manifest names; this reader does not accept a replacement candidate or condition grid.

Outputs are new `REVIEW.json` and `REVIEW.md` files inside the chosen child directory here. Existing outputs cannot be overwritten. Missing, inconsistent or incomplete required evidence yields OPEN and exit status 2; no partial results are promoted to a complete pass. A read limit of 550 seconds bounds this supplementary command. `PREPARED.json` preserves the actual preparation time and input source identities. Source syntax was checked with `ast.parse`; no functional run or redundant game test was performed during preparation.

The restrictions remain no JavaScript or TypeScript, servers or listeners, RLScience or other cluster, remote compute, GPU, Lean/lake, protected writes, git commit/push or online posting. The reader creates no subprocess and uses one low-priority assigned CPU core. Its later outcome is a posthoc evidence review, never an added predeclared experiment or another strength sample.
