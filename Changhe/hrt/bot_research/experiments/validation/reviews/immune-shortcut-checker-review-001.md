1. Persistent-state canonicalization. CONFIRMED FOR THE FROZEN POLICY'S VALUE STATE. `freeze(vars(policy))` compares every instance field, rather than a manually selected subset. Type tags distinguish booleans, integers, floats, lists, tuples, sets and frozensets. Lists retain order; dictionaries and sets are canonicalized by contents. Dataclasses include their module, class name and every declared field. Functions include their module, qualified name, named free-variable cell contents, defaults, keyword defaults and function attributes. This reaches the foreign delegate's closure dictionary, its requested cells, foreign flags, opposing-turret flags and replanned layouts, as well as its captured parameters. Unknown types fail with an exception rather than being silently omitted. The four declaration fixtures cover closure-value equality and inequality, dictionary order independence, and list/tuple distinction.

The canonicalizer does not preserve object identity, alias relationships, dictionary insertion order, function bytecode or mutable module globals. That is suitable for the reviewed frozen fields, which are compared by value, use dictionaries by key, and have their function definitions pinned. Shared module caches are explicitly excluded. This is not a general serializer proving equivalence of arbitrary Python objects. The case receipts retain equality booleans, not full snapshots of canonical states, so independent reconstruction of every comparison requires rerunning the pinned checker.

2. Foreign dispatch and shortcut classification. CONFIRMED UNDER DEFAULT PARAMETERS AND MATCHING STATE. The pre-call `native` test reproduces the inherited caller's condition because default foreign delegation is enabled: the alternate policy must be absent and the current buildings must contain no unrequested cell. Existing delegation therefore remains foreign even if later observations contain no unfamiliar cells. The `fast` flag additionally evaluates the exact shortcut predicate. It is computed from the shortcut instance; if H1 passes, both instances' corresponding state agrees and the native/foreign assignment is common to both. On a divergent run, foreign counts should be read as the shortcut-side classification, not as proof that both implementations followed the same path.

3. Prefixes, observations and action identity. CONFIRMED FOR THE PROCESSED ROUNDS. Fresh instances are constructed once per history. Candidate prefix turns are checked against the prescribed lists and replayed without calling either instance, matching `OpeningPrefix` semantics in the original selected-C runner. The actual candidate observation comes from an Engine already advanced by the preceding retained actions. Each policy receives an independent deep copy; value mutation of that argument is checked after the call. Both generated JSON action lists must equal each other and the retained candidate actions, preserving list order. Sequential `apply_action` checks each generated list against a reconstructed own state. The reconstructed next-roster identifier may differ after prior expirations, but identifiers do not affect action acceptance; this does not weaken the legality check. The replay Engine maintains the actual identifiers.

Each processed record pair must exactly equal normalized `Engine.play_round` output. This checks both players, all retained action events, costs, combat, income, roster expiration, snapshots, round and player numbering, and any terminal result for that pair. Rejected actions and bot errors are prohibited. Opponent policies are not regenerated; their recorded actions are replayed. That is adequate for reproducing the candidate responses on these fixed public histories, and is not a new matchup evaluation.

4. Complete-stream gap. OPEN IN THE PINNED CHECKER ALONE. `case` iterates through `row['rounds']`, but does not assert that the replay has exactly `2 * (rounds + 1)` records. A file with additional trailing records can therefore pass all processed-pair checks while some records remain unread by the replay loop. Selected-C cases also use `engine.result == row['result']` without separately requiring a non-null terminal result, so that comparison alone accepts two null results. High-factory cases dereference the terminal result and compare final HP, winner and reason. The existing strict replay-audit helper contains stronger shape checks, but this checker imports only its normalization function and does not invoke those checks.

This is a missing validation condition, not evidence that any pinned history is malformed. A separately pinned, no-policy check of exact record counts, positive valid round counts, bounded prefixes and non-null final recorded/result outcomes can establish that the existing corpus closes this gap. Combined with successful protocol151 per-round replay receipts, it would support the complete-stream sentence. The author has accepted this supplement; I have not verified its result here.

5. Corpus and counts. CONFIRMED AS DECLARED COVERAGE AND CHECKER LOGIC. Publication recomputes actual calls from completed case receipts and requires the expected call and prefix totals when H1 would pass. The declaration's 1204 total is not independently re-summed from all 72 result files in this source-only review. These histories remain reused development evidence.

6. Timing scope. CONFIRMED MEASUREMENT BOUNDARIES; CAVEAT REQUIRED. Timers bracket the complete policy `__call__`, including the shortcut's own guard and inherited foreign delegate, and exclude JSON normalization, legality checks, state comparison and replay. Each history uses a fresh child interpreter. Within it the policies share imported modules and caches, with parent first on odd rounds and shortcut first on even rounds. CPU time uses `process_time`; wall time uses `perf_counter`. The publisher computes maxima only across the two high-factory histories, and totals across all measured cases, as declared.

Before either timed call, line 160 calls `policies[1].eligible(obs)` on native observations for classification. This is an untimed extra guard evaluation that can populate route/layout caches. The shortcut still repeats and pays for its guard inside its own timed call; the concern is cache preconditioning, not that its measured call omits the guard. The existing shared-cache caveat should explicitly name this preflight. H3 can describe measured policy CPU under this instrumented execution; it does not establish a cold-start or portable bound. The author plans a dated caveat and a separate fresh-process follow-up without classification preflight. Neither is part of this pinned checker review.

7. Publisher and failure handling. MOSTLY CONFIRMED, WITH A CONDITIONAL VERDICT-LABEL DEFECT. Per-case exceptions and 300-second timeouts produce retained failure files. Existing case or failure files prevent silent retries. H1 requires all 74 case files, no failure files, every case's action/state comparison to pass, matching declaration hashes, and the exact aggregate call/prefix counts. Thus a normal generated failure cannot silently become a successful H1 verdict. H2 requires a positive shortcut count. H3 independently requires both high-factory cases and their measured shortcut maximum CPU below three seconds. The final JSON pins the declaration and completed case receipts.

However, the publisher prints H1 OPEN for every unsuccessful H1 outcome, even when a retained action/state difference directly falsifies the declared finite equality. The proof says a discrepancy refutes H1 until separately explained. If such a difference occurs, a dated report qualification must identify H1 as REFUTED under those conditions while preserving the original publisher output. This reporting defect does not change an all-success verdict. Missing or timed-out cases, by themselves, leave an equality claim OPEN.

The publisher's installed-candidate and terminal-validation integrity sentence also requires the team's separate integrity evidence: this checker checks the installed candidate hash at declaration, then exercises the frozen parent, and does not continuously pin the installed candidate or terminal-validation artifacts. It does not write either one. Successful protocol151 receipts will support finite response/state reproduction and the measured timing claim with the qualifications above, not a universal foreign-deadline theorem, improved game strength, or final-candidate replacement.
