# Priority numerical reporting and lifecycle findings

Observed UTC: 2026-10-23T06:43:15.120628+00:00. Source hashes and immutable copies: evidence/numerics_runtime_source_audit.json. These are source-level findings, with small local counterexamples being saved separately. No numerics process is modified or interrupted by this lane.

1. The current ledger does not compute a measured union of active intervals. train.py closes a gap interval after the gap and stores only active_seconds within the whole wall interval. ledger.py spreads that fraction uniformly and takes the maximum density across workers. Actual active intervals cannot be recovered from those totals. For example, worker A has record [0,2] with one active second actually spent in [0,1], and worker B has record [0,1] with one active second. True union is 1 second, but the density procedure returns 1.5. Another alignment can undercount. Please record actual numerical step or chunk start/end timestamps, splitting out gaps before union. The present number must be labeled an estimate, not a measured 96-hour certificate. Preserve historical records and label any unrecoverable uncertainty. No wall-clock extrapolation repairs it.

2. validate() concatenates weights from overlapping core, origin and axis samplers, then labels their sum a physical-volume integral. Individually each sampler weight is valid for its own support. Their raw sum integrates the field with support multiplicity: the origin ball is counted twice, and the axis tube adds another copy where it overlaps. A ratio of such norms does not generally cancel the spatially varying multiplicity. Keep the axis/origin diagnostics separate and use the disjoint core+shell samples for global physical-volume norms, or implement a documented mixture-density weighting. Our independent shells already use uniform physical volume. Existing trainer eps_m values are a different weighted measure until repaired.

3. LBFGS retains curvature history across resampling every five outer steps. The objective is fixed inside a line search, but a new collocation set changes the objective between those blocks. The prompt requires explicit history handling when collocation changes. Reset LBFGS state at resampling, or keep one fixed set for a full deterministic stage and document the change.

4. An exact resume in the middle of a resampling block cannot reproduce the next iterate: ckpt_last saves sampler generator state but not the current batch, and resume sets batch=None and draws a new batch. This is hidden by Adam resample_every=1 and matters for the planned LBFGS resample_every=5. Save the current batch (and its identity), or save a generator state from before that batch and reconstruct it. Also restore sampler.cfg from its saved state when staged sampling overrides are used.

5. The in-memory NaN rollback is not a frozen checkpoint. model.state_dict() returns tensor references; ck["model"] is not cloned before assigning last_ckpt_state. Parameter updates mutate those referenced tensors. model.load_state_dict(last_ckpt_state["model"]) can therefore reload the already corrupted values. The optimizer state is also left corrupted. Reload the atomic disk checkpoint with the full optimizer and sampling state, or keep independent deep clones. The saved disk bytes remain usable.

These fixes concern measurement and reproducibility, not evidence for or against exact profile existence. I will verify the repaired code and matched checkpoint outputs when they appear.

6. The C drift term is multiplied twice in validate() normalization: physics.momentum_terms returns C_dzU = C*dzU, then validate adds abs(C)*l2(C_dzU). This gives C^2*||dzU|| rather than |C|*||dzU||. Current C=0 runs are unaffected. Remove the outer factor for future nonzero-C runs.
