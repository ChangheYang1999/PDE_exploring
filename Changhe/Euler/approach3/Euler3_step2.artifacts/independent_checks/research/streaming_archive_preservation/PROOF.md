# Exact reconstruction while packing an archive from its end

Statement. Let B be a finite byte string representing a supported NPZ archive. Write B as E_0 C_0 E_1 C_1 ... E_(n-1) C_(n-1) S, where each C_i is a DEFLATE member, each E_i is the preceding ZIP envelope, and S is the final envelope. Suppose each array codec is an invertible permutation of its data bytes and that recompressing the exact NPY header and decoded data reproduces C_i byte for byte. Suppose durable file writes, renames and truncations have the stated order, and no other writer modifies these files. Then the following procedure retains sufficient data to reconstruct B after each completed filesystem operation, including interruption between operations.

Notation and procedure. Retain every E_i and S in a durable manifest. Let b_i be the offset immediately before E_i, with b_0=0. Initially retain B as the source prefix. Process members in decreasing index order. For member i, first write and read back its encoded array; compare its decoded bytes, NPY bytes and recompressed C_i against the source. Then atomically commit that member's complete reconstruction record to the durable manifest. Only after this commit truncate the source prefix to b_i. Do not use numerical rounding or discard mantissa bits. At the end verify the reconstruction of the whole original byte string before recording completion and removing the now empty prefix.

Proof. Initially the original source is available. After committing members i+1 through n-1 and truncating, the retained source contains every E_j C_j with j<=i, and the manifest and encoded arrays reproduce every later E_j C_j and S. This is the induction invariant. Writing member i's new payload, or stopping before committing its record, leaves the source intact, so the invariant still holds with the previous boundary. Once its record is committed, the same prefix and that record both supply E_i C_i. An interruption here leaves redundant copies. Truncating to b_i removes only bytes reconstructed by the committed suffix records; the invariant holds with i decreased by one. Induction reaches an empty source prefix and a complete reconstruction. Concatenating the components in their original order gives exactly B.

Manifest writes use a temporary file, file fsync, atomic replacement, and directory fsync. The encoded payload is fsynced before the manifest commit. Source truncation is fsynced afterward. These ordering assumptions address process interruption and a filesystem that honors the stated durability semantics; the argument does not guarantee survival of arbitrary storage-device failure. A source rename is performed only after a durable manifest identifies both its original path and the prefix path, so either name identifies the initial copy after an interruption.

Dependencies and scope. This is a byte-preservation argument, conditional on exact codec reconstruction and the filesystem assumptions. Cryptographic hashes and readback tests are implementation checks, not a mathematical proof that unequal strings cannot collide. The implementation additionally compares actual decoded or recompressed bytes where available and checks the complete original SHA256. It rejects unsupported ZIP members, object arrays, overlapping member offsets and altered committed payloads. No claim about the Euler equations or the numerical accuracy of stored arrays follows from this storage procedure. No Lean or Lake build is used.
