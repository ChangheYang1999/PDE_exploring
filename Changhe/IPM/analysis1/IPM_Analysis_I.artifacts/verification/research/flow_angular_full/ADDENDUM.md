# Mandatory precision, ancestry and evidence qualifications

This addendum is part of PROOF.md. Its scope overrides any broader reading
of the phrase "frozen flow certificate" in the title.

The candidate arrays are regenerated by the frozen AngCache.factors at
128 bits, with n=1,...,261 and its integer jw array constructed at128bits.
They are not authenticated historical arrays from a numerics-lane run.
Transferring them to such a run remains OPEN. Each node has one base cell
and one left/right ancestry; induction on its bits proves that the
stack enumeration and fresh ancestry enumeration construct the same
endpoint balls. The ball midpoint and radius are recorded exactly as
integer mantissa and exponent, alongside the ancestry, not inferred from
the four-float key. Absence of duplicate keys plus this deterministic
single path justifies clearing the cache in this finite regeneration.
No statement that the float key determines an arbitrary Arb ball is used.

The actual factors[fam][3] arrays, including C and S separately, are
extracted and compared byte for byte with eight exact-dyadic tables.
The startup of every checker and fresh replay regenerates a representative
at each depth, including resumed processes. Those actual output tables
must agree with the topic73 archive and satisfy all4176 Fraction
inequalities. Every subsequent row repeats the byte comparisons. The
full footer must observe precisely all eight width values. The old73
remainder-expression calculation alone is not proof about actual output
arrays. The old221 coefficient arrays are compared byte for byte where
those nodes occur in the new run.

Arb512 and Arb1536 share FLINT; only mpmath.iv is implementation-distinct.
The third method uses a different mathematical evaluation and complete
regeneration, but its source128 ancestry replay is a reproducibility
check, not an independent arithmetic implementation. Arb comparisons
must be certain, with finite balls. Each mpmath interval comparison must
return the Python value True. Binary64 to either library is exact and is
checked against as_integer_ratio in diagnostic tests. No float conversion
of reference endpoints is permitted in acceptance comparisons. Contexts
are reset before every source and reference phase, and fresh pi is
computed at the reference precision. Taylor's theorem needs true
half-width <= d; the code may enforce strict inequality as a stronger
finite check. Strictness is not needed for the theorem.

All source arrays and geometry floats must be finite, every radius and
remainder nonnegative, and d positive. The axis predicate a_lo<=0 iff
l=0 is checked separately from the seven geometry checks. Source array
hash order is a C-contiguous little-endian <f8 array with shape
(2,3,3,261), ordered midpoint/radius, cos/C/S, derivative0/1/2, mode1..261.
Remainders have shape(3,261); geometry has order cos_a endpoints, cos_b
endpoints, sin_a endpoints, sin_b endpoints, a_lo,b_hi,d. Endpoint-ball
records and the ancestry have separate canonical JSON hashes. Hashes do
not prove containments: the engines and complete replay perform them.

Every accepted row is flushed and fsynced. The header pins code, proof,
input data and source hashes, library versions and loaded numerical
binary hashes. The process asserts hardware round-to-nearest and records
Arb/iv precision. Restart validates the header, every complete prefix row
and its chain, then resumes its declared next node. Only a final line
without its terminating newline may be removed as an uncommitted record,
and the removal is recorded. A newline-terminated invalid record, changed
input, duplicate row, altered count, bad chain or incomplete footer is
rejected. A partial prefix never receives a full completion verdict.
The third replay regenerates every source array and checks every box;
its all-row count is not replaced by a sampled replay.

The first actual Opus5.5 review is retained. Its proof acceptance was
conditional on these obligations. Its assertion that strict d is needed
was stronger than necessary; its historical-run concern is resolved by
the restricted scope above. Its source-remainder concern is resolved by
checking actual arrays, without enlarging the old topic73 claim.
