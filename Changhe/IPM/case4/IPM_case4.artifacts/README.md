# Accompanying artifacts of the IPM case 4 report

This folder accompanies the report IPM_case4.report.md beside it. It holds the documents, code, manifests, records and
small checkpoints of the isolated 860-generator campaign. Nothing in it is copied from the read-only handoff
IPM_StageXIII_GitHub_handoff, which sits beside this folder in the repository. The numerical scripts require that
handoff; the archive checks below do not.
No optimizer state in these files is an exact PDE solution or a demonstrated stationary point (see the report, item 10).

## Contents

- Required documents: START_HERE_NEW_RUN.md, LINUX_QUALIFICATION.md, BASIS_860_IMPLEMENTATION.md, EMBEDDING_TESTS.md,
  OPTIMIZATION_860_LOG.md, RESULTS_860.md, RUNBOOK_860.md. They were written during the campaign by the numerics
  workstream and keep its working vocabulary (gate names G2 to G5, slice numbers, internal rulings). Where they and the
  report differ, the report is authoritative: it distinguishes independently checked scientific results, fixed at the
  data cut 2026-10-26T04:00:00Z, from later observations that were not checked independently.
- work/research860/: the new code added to the handoff layout during the campaign. The handoff files of the working copy
  were byte-identical to the handoff at the end of the run; the one added file in the handoff layout,
  research/base/inputs/assessment_grids_stage12.json (11 MB), is generated by the handoff's own asset preparation step
  and is not included.
- bin/: supervisor, launch, monitoring and bookkeeping scripts of the campaign (supervise860_v4.sh ran the long run).
- outputs/manifests/: frozen code manifests (code_manifest_g4_v2.json is the manifest of the pilot and the long run) and
  environment.json (host, Python 3.9.25, numpy 1.23.5, scipy 1.9.3, OpenBLAS 0.3.20 with one thread per process).
- outputs/integrity/: SHA-256 and stat listings of the protected source before the campaign and at five later times.
- outputs/qual/, outputs/checks/, outputs/tests/, outputs/diag/: Linux qualification, baseline replays, unit and
  embedding tests, diagnostics (rounding model, replay diagnosis). The qualification's working replica of the
  handoff's research inputs is omitted; its result summaries are kept. Files byte-identical to a handoff file were
  left out (checked against the SHA-256 listing of the protected source).
- outputs/g2/, outputs/g3/: evidence of the embedding gate and of the feasible-chart gate (g3/g3_v1/t4.json), and the
  benchmarks and ETA records.
- outputs/campaign860/: the immutable 860 seed reproducing accepted278 (seed/seed_860.json and .npz), the campaign
  policies, the closed first pilot root pilot_g4_v1, and the main root pilot_g4_v2 (repaired pilot and long run):
  accepted snapshots 1 to 88 (JSON), commit events 1 to 155, assessments and their ledger, slice records, guard session

- restore_paths.py: copies the archive, optionally replacing path tokens (next section).

Run logs, session transcripts, the Python environment, resource sampler streams and arrays above 1.5 MiB (other than
the two checkpoints) are not included.

## Portable paths and historical hashes

Host paths in archived records and documents are represented by tokens:
@SOURCE_REALPATH@, @WORK_REALPATH@ and @OUTPUT_REALPATH@ (the three realpaths recorded at the top of the report),
@NUM_DIR@ (the parent of the working copy and outputs), @CASE4_TREE@ (the parent of the protected source), and tokens
for other host prefixes. MANIFEST_PUBLISHED.json retains the original SHA-256 and the paths_tokenized flag.
restore_paths.py can replace explicitly supplied tokens in a separate copy. A file regains its original bytes only
when all its tokens are mapped to the original prefixes and it has no other publication edits.

The published scripts now locate work/, outputs/ and bin/ relative to their own location. Scripts that need the
protected handoff or independent reference inputs read IPM_SOURCE_REALPATH or IPM_REFERENCE_DIR from the environment.
The reference inputs source_Nn_pinned.json and embed_seed_coefficients.json are not included here. The path edits do
not change numerical formulas, but they do change source hashes. The frozen manifests under outputs/manifests/ remain
historical evidence; they do not certify the edited scripts. New numerical runs require fresh qualification and new
manifests. MANIFEST_PUBLISHED.json records the current published hashes and identifies publication edits.

## Exact archive checks

Run these commands from this folder. They use Python's standard library and Bash, check every published file and
parse the scripts without importing or executing the numerical code:

```sh
python3 -B - <<'PY_CHECK'
import ast
import hashlib
import json
import subprocess
from pathlib import Path

root = Path.cwd()
manifest = json.loads((root / "MANIFEST_PUBLISHED.json").read_text())
expected = {entry["path"] for entry in manifest["files"]}
actual = {str(p.relative_to(root)) for p in root.rglob("*") if p.is_file()}
assert actual == expected | {"MANIFEST_PUBLISHED.json"}, "file inventory mismatch"
for entry in manifest["files"]:
    path = root / entry["path"]
    assert not path.is_symlink(), entry["path"]
    data = path.read_bytes()
    assert len(data) == entry["bytes"], entry["path"]
    assert hashlib.sha256(data).hexdigest() == entry["sha256"], entry["path"]
for path in root.rglob("*.py"):
    ast.parse(path.read_text(), filename=str(path))
for path in root.rglob("*.sh"):
    subprocess.run(["bash", "-n", str(path)], check=True)
for path in root.rglob("*.json"):
    json.loads(path.read_text())
print(f"Verified {len(expected)} files; Python, Bash and JSON syntax passed.")
PY_CHECK
```

To make a separate copy without changing any archived record, run:

```sh
COPY=$(mktemp -d -t ipm-case4-860.XXXXXXXX)
python3 -B restore_paths.py "$COPY"
cp MANIFEST_PUBLISHED.json "$COPY/"
printf '%s\n' "$COPY"
```

Tokens stay in place unless mappings are supplied to restore_paths.py. Do not treat these archive checks as a rerun
of the scientific computations. The protected handoff, its generated assets, the omitted independent reference
inputs and the numerical environment are needed for qualification and optimization. The recorded environment was
Python 3.9.25, numpy 1.23.5, scipy 1.9.3, psutil 6.0.0 and threadpoolctl 3.6.0, with one OpenBLAS thread per process.
The independent exact-arithmetic verification programs are not part of this archive.

## Monitoring and stopping a complete campaign copy

The campaign was terminated at the end of the reported run. The published campaign root is an archival record,
not a resumable copy: its snapshot arrays and commits are incomplete, and its later state and trajectory records
do not share the scientific data cut. The state-131 checkpoint is explicitly unverified. Archived process
identifiers do not establish that a campaign is currently running.

Only in a complete, separately qualified campaign copy, run the following from the directory containing bin/,
work/ and outputs/. These are the monitoring commands referred to in the report:

```sh
ROOT=outputs/campaign860/pilot_g4_v2
python3 -B bin/status860.py "$ROOT"
ps -p "$(cat "$ROOT/SUPERVISOR_PID")" -o pid,ppid,etime,args
cat "$ROOT/HEARTBEAT.json"
tail -5 "$ROOT/supervisor.log" "$ROOT/trajectory.jsonl"
ls "$ROOT/commits" "$ROOT/snapshots"
du -sh "$ROOT"
```

After confirming a live worker in that complete copy, the safe-stop command is:

```sh
touch "$ROOT/STOP"
```

The slice handles the request at a trial boundary. STOPPED_FOR_DIAGNOSIS, DRIVER_REFUSED, FAULTED or
SESSION_BUDGET_EXHAUSTED requires diagnosis before relaunch. RUNBOOK_860.md preserves the campaign's historical
procedures and pilot restart tests. The run used 5,000 s slices and 8 workers. A manifest change cannot resume an
old root, and restart after the final forced termination was not tested. No restart command for the incomplete
published root is supplied.
