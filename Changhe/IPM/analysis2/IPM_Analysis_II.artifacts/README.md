# Artifacts of the S1 theory report (IPM case 4, a posteriori analysis)

This folder accompanies the report. It holds the proofs, numerical certificates, closure conditions and
reproduction instructions, together with selected programs and data. Some inputs of the original verification runs
are omitted from this published subset, as listed below; complete reproduction requires those inputs.

## Contents

- S1_PROOFS.md: the proof parts P1 to P99, P101 to P106, P108 and P111 that the report cites.
- S1_NUMERICAL_CERTIFICATES.md: each certified number with its method, its certificate file and its independent audit.
- S1_CLOSURE.md: the nonlinear closure conditions, the margins actually certified and the remaining gaps.
- S1_RESTART.md: the full reproduction instructions, the expected outputs and how to continue the research.
- certificates/: the certificate programs and records, one subfolder per proof part (529 files, about 35 MB).
  - MANIFEST.txt lists the files in this folder with their SHA-256 hashes.
  - MANIFEST_FULL.txt lists the complete packet of 697 files (about 491 MB) that the reproduction runs used.
  - OMITTED.txt lists the 168 files of that packet that are not shipped here, with sizes, hashes and reasons.
- scripts/: the restore and rerun drivers (restore_layout.py, run_checks.py, run_recomputations.py,
  run_late_rechecks.py), the closure arithmetic (closure_arithmetic.py) and the independent recomputations
  check_*.py, each with its JSON record. build_proofs.py and collect_certificates.py are included for transparency
  only, because the part-by-part proof tree they read is not shipped.
- numerics/: the code and data of the box-covering and far-field certificates, of the exact references (state 131,
  the refits, d2) and of the floating-point diagnostics. numerics/README.md gives the commands item by item.
- SHA256SUMS.txt: the SHA-256 hash of every file in this folder.

## Environment

The programs need Python 3.12 (tested with 3.12.13), python-flint 0.9.0, mpmath 1.3.0, sympy 1.14.0 and numpy. The
numerics programs also need scipy. No GPU and no network access are needed. The check suites run sequentially;
some numerical covering commands use multiple workers as specified in numerics/README.md. Set OMP_NUM_THREADS=1
and OPENBLAS_NUM_THREADS=1. Earlier Python versions fail on the large integers. Below, python3
means this interpreter.

The original case 4 checkpoints are not copied here. The programs read them from the published case 4 artifacts
folder, Changhe/IPM/case4/IPM_case4.artifacts. Relative to this folder in the repository, that is
../../case4/IPM_case4.artifacts. The copies used during the research have the same SHA-256 hashes as those files.

## Commands (run from this folder)

1. Verify the published files:

       sha256sum -c SHA256SUMS.txt

2. Restore the layout that the programs expect, and supply the original checkpoints. BASE is a new, empty directory.

       python3 scripts/restore_layout.py certificates BASE ../../case4/IPM_case4.artifacts --relocate

   Expected output: "prepared relative input layout" and "529 files restored under BASE; 0 hash mismatches".
   Certificate programs use relative paths from BASE; --relocate also copies the exact refit inputs into that
   layout. Publication review tested this restore on the shipped subset without the omitted checkpoints, with
   zero hash mismatches, and checked script syntax. The full suites were not rerun.

3. Rerun the checks (113 programs) and the independent recomputations (32 programs), each on its own fresh restore:

       python3 scripts/run_checks.py certificates BASE
       python3 scripts/restore_layout.py certificates BASE2 ../../case4/IPM_case4.artifacts --relocate
       python3 scripts/run_recomputations.py certificates BASE2

   On the complete packet these gave "every program exits with status 0 and no output DIFFERS" (113 programs, about
   40 minutes on one core) and "32 programs, 0 not reproduced" (about 17 minutes); S1_RESTART.md sections 3 and 9
   give the details. Several programs read or compare derived records above 1 MB that this folder omits. Such a
   program stops with a missing-file error or reports a hash difference, and certificates/OMITTED.txt names the
   missing file. Those reruns have not been tested on this folder. Code and provenance path repairs also change
   hashes; records bound to the original files retain their historical hashes and may report a difference.

4. The late rechecks of the whole-plane bounds of P95, P99, P101, P104 and P105 (S1_RESTART.md section 3a) need the
   two exact d2 records of P95 (145 MB and 165 MB). These are not shipped, so this folder cannot rerun them. The
   records were generated by certificates/P95_refit_global_hypotheses/build.py and build_derivatives.py from the exact
   reference numerics/data/nb_d2_exact.json. Their hashes are in OMITTED.txt, so a regenerated copy can be checked
   against them. The late driver requires its restored base directory to be named research.

5. Closure arithmetic (the threshold tables of S1_CLOSURE.md section 8):

       python3 scripts/closure_arithmetic.py

6. Exact reconstruction of the reference states from the original checkpoints (S1_RESTART.md section 5):

       python3 scripts/run_checks.py certificates BASE --recover --only P1_source

7. The numerical certificates (state 131 matrix and far-field bounds, annular lower bounds of the weighted residual
   norm, exact references): follow numerics/README.md and run the commands from inside numerics/.

## Notes

- To keep the folder under 50 MB, it omits 168 files. They are the run logs, the copies of the two original
  checkpoints, and derived records above 1 MB, among them the two d2 records (310 MB together) and the 65 MB cell file
  of the box covering for state 131. Each omitted file is listed with its SHA-256 hash.
- Internal working references were removed from 23 of the Markdown audit and proof texts in certificates/. Their
  hashes in MANIFEST.txt therefore differ from MANIFEST_FULL.txt. An audit program that checks the hash of one of
  these texts (for example the contract audit of P105) reports the difference.
- Identifiers of the form Vnnn in the audit and proof texts refer to numbered entries of the independent verifier's
  ledger, which is not published. S1_PROOFS.md and S1_NUMERICAL_CERTIFICATES.md contain the corresponding results.
- Input paths in certificate programs are relative to the restored base. Numerical shell drivers locate numerics/
  relative to their own files and use Python from PATH (or the PYTHON environment variable). Their case 4 inputs are
  at ../../../case4/IPM_case4.artifacts relative to numerics/. Before using a numerical shell driver, run:

      mkdir -p numerics/runs

  Historical queue drivers still depend on omitted fit outputs, logs or other intermediates. In particular,
  nb_launch.sh needs the omitted algebraic_n12_m10_k16.json input. refresh_artifacts.sh is an archived packaging
  helper requiring the original, unshipped source layout as an argument; it is not a reproduction command.
- Current manifests include the relative-path repairs to scripts and provenance fields. MANIFEST_FULL.txt and
  OMITTED.txt preserve the original record of the complete packet. Stored code/input hashes in historical audit
  records are not replaced with hashes of edited files; a hash mismatch alone is not a new mathematical result.
- Files above 1 MB retained here are the proof collection and exact mathematical input records used by the
  documented calculations. No large run log or scratch file is included.
