# Portable inputs for the consolidated residual table

Status: audit criterion and proof written before package computation. This is a finite artifact-integrity result, not a new PDE theorem. P313 checks the original consolidation against this verifier's own evaluation arrays. The present question is whether the numerics lane's published package and run archives contain matching inputs without reading the live verifier lane during reconstruction.

## Statement and definitions
Let E be the finite set of123 (folder,label) audit entries established by P313. Each entry has48 measurement keys (two velocity kinds, four fields, six radial bands). Let h(e) be its registered coefficient-archive hash. A portable representation consists of the exact regional JSON file for each folder, an accessible coefficient archive with hash h(e), and its scalar metadata. Allowed reconstruction roots are numerics/artifacts/verifier and numerics/runs, plus the target CSV in artifacts for comparison. The independent reader must not fall back to the live verification directory when reconstructing the data. The original P313 records may be read separately as an oracle to verify source integrity; they are not inputs to the portable row computation.

Claims to check: every required regional file is packaged with the same bytes as its original; the packaged inventory and its61 archive references are valid; every h(e) has a matching accessible file; scalar metadata and regional values reconstructed solely from these portable inputs reproduce the123-entry,5904-row CSV; current code/artifact copies and checksum records agree. This does not assert that the numerics script was executed or that every README solver command was rerun.

## Complete argument
For each regional file, byte equality implies equality of every parsed finite key/value record. Matching its operational hash to the frozen original establishes the intended input identity, subject to the usual collision assumption. Every required archive is selected by its full hash, never a rounded beta or filename prefix. Equal bytes imply equal parsed scalar arrays. Multiple paths or labels with the same hash do not create a second state identity; different hashes are not evidence of different mathematical fields.

The independent reader forms a finite function R on keys (folder,label,kind,field,band). If its key set equals the target CSV key set and all associated residual values, counts and scalar metadata agree, then the two tables are equal as finite keyed data. This is proved by extensionality of finite functions. Hash identity of the regional files and coefficient archives separately connects this reconstruction to P313. The reader reports every missing key and unmatched hash, so a partial reconstruction cannot pass as complete.

An archive inventory is portable if each registered relative path resolves within the permitted package root and its bytes match the stated hash. A coefficient archive elsewhere under numerics/runs can supply another required state, but this must be reported as an additional dependency rather than attributed to the61-file inventory. Exact preservation of the residual tables does not imply that the package includes the large raw evaluation arrays or an independent inverse implementation. The standalone package may reproduce the already computed tables while the original verifier evidence is needed to reproduce their generation.

Source scripts and their artifact copies are read only. Equal hashes confirm copy identity at the observed time, not runtime behavior. A full-hash independent reader demonstrates data sufficiency, not that an unexecuted filename-based resolver makes the same selection on every machine. Static review can identify fallback branches or missing guards; any claim about an unexecuted command must remain explicitly limited.

## Scope and failure handling
The current README contains broad scope and execution claims that must be checked rather than trusted. In particular, manufactured controls must be excepted from an all-forced statement; the eight Q entries consist of six48-point restarts and two tighter secant states at12 and48 points. Solver reruns, GPU use, software installation, JavaScript/TypeScript, servers, the RLScience cluster and Lean/Lake builds are not part of this audit. No teammate code is executed or imported. All writes and generated evidence stay in this verifier directory. Initial failed checks and source changes are retained with real UTC times.
